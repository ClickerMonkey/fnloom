## Findings worth knowing first

1. **"You there?" (session `ses_rrat1k0sietg06pa34zn`, in `harness/.harness`, 2026-11-17, model `nvidia/nemotron-3.5-super-vl:free`).** "Create a place to track tasks" ran 24 iterations and failed on max-iterations. The root causes, ranked:
   1. Every database fn was held by a pending system review ("database/create_table changed and waits for an admin to approve it"). The model was never told this.
   2. The hub's words hid or contradicted it:
      - `load_fns` refused with a bare "unavailable now" (`contextor/views.ts:44` drops `availability.detail`).
      - `fns_search` silently drops unavailable fns (`fns/search.ts:184`).
      - The context render claimed the database fns were "in your tools now" (`contextor/render.ts:105`).
      - `load_context` returned `fns: []` with no refusal.
   3. Undo/Retry doesn't trim the session transcript or the loaded tools and context (`chat/undo.ts`). The retry still saw the whole undone turn (182k chars), and the note said "It had changed nothing."
   4. Nothing tells the model to stop and report when it is blocked, and the tool-failure guard didn't fire.
   5. A weak free model: strings for arrays, made-up run ids, calls to unloaded tools.
   6. Suggestions scored the web fns at about 0.98 for every message, including unrelated ones. The embedder or scoring is suspect.
2. **The Claude "failed to send" is a race in shared code.** `settledRun` (`web/src/chat/state/widget-host.ts:30`) resolves on the `done` status event before the run's `outcome` is fetched, so it reports "It ended done." as a failure. Widget saves and actions have the same latent bug.
3. **Two violations of the library rule were found.**
   - `hub/src/contextor/ollama.ts` is an Ollama provider living in harness. It belongs in a new `@aeye/ollama`.
   - The context list search is in-memory substring matching (`hub/src/query/sources.ts:300`), and other `RowsSource.search` lambdas do the same.
4. **Ollama `/v1/systemone` exists (v0.35+).**
   - At most 64 questions per request, and input up to 64 KiB.
   - Images go in a top-level `images` field.
   - Its answer shape differs from what aits parses for OpenRouter (`noul`, and probabilities keyed by index).
   - aeye's `DecisionRequest` has no images.
   - Nothing in the hub calls `ai.decide` today. The current "decision model" for suggestions is a chat model asked for JSON.
5. **SSO.** ayepi has no OIDC: `@ayepi/auth` is HS256 only, with no JWKS. `@ayepi/mcp/oauth` already has discovery, PKCE, authorize and exchange, so lift it into `@ayepi/auth` and add OIDC id-token verification there. Turning SSO on makes `member` real, but most pages are built around the admin, so the UI needs a pass by role.
6. **Single instance is already declared.** `system.json` has `instances: one|many`, but it only refuses a second install and never reaches `SystemRecord`, `SystemView` or the UI.
7. **Examples.** Hub and system fns mostly have them. Kind-derived fns (queries, generated table fns, forms, API, MCP, agents) get none, because `KindDescription` has no `examples`. `catchUp` (`hub/src/fns/create.ts:71`) may never have backfilled examples for older fns.
8. **System-specific UI hardcoded in web/core.**
   - Claude: `web/src/claude/**`, two pages, routes, an always-shown nav item, and `core/src/claude.ts`.
   - Widgets: `web/src/components/widgets/*`, `core/src/widgets*.ts`, plus prompts naming `widgets/make_widget`.
   - Database: `DrillDialog` calls `database/drill_down`.
   - The SDK `client()` has no pages or nav contribution.
