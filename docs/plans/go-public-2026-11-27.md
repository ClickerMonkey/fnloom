## Decided

- **Name: fnloom.** npm package `fnloom` (unscoped), the command `fnloom`, the site's name. The GitHub repo is renamed
  `ClickerMonkey/harness` → `ClickerMonkey/fnloom` (GitHub redirects the old address). The internal workspaces keep
  their `@harness/*` names for now.
- **One npm package** holding the hub, the web app and every premade system (`@harness` isn't a scope we own).
- **Trusted publishing:** `fnloom@0.0.1` was published by hand as a placeholder; npm trusts
  `ClickerMonkey/fnloom` `.github/workflows/release.yml`, environment `npm`, for publish. A `v*` tag publishes.
- **History** (hitloop set `harness-go-public`): `.hitl/` is no longer tracked (it stays on this computer); the
  history was rewritten once before going public to replace a made-up but real-looking Gmail address in the test
  scenarios and to drop the old `.harness-test/` data (it held throwaway test keys).
- **The site** is on GitHub Pages at https://fnloom.com (clickermonkey.github.io/fnloom until the DNS is in; the name, package and repo come from
  `site/site.config.json`).

> I bought fnloom.io, .com, .ai, and .dev and plan on using those

- **Domains:** fnloom.com is the site (GitHub Pages for now, `CNAME` written by `npm run site:publish` from
  `site/site.config.json` "domain"); fnloom.io, .ai and .dev forward to it. Phil adds the DNS records (A records to
  GitHub Pages' 185.199.108–111.153, `www` CNAME to clickermonkey.github.io, forwards for the other three).

## Phil's follow-up (verbatim)

> Yeah I mean by default you should get no system basically and installing one is what should pull those things in. And packaging in puppeteer does that make any sense?

- **Decided:** `fnloom start` starts no systems (just the hub and the app). Each premade system brings its own
  dependencies when installed (puppeteer arrives with `fnloom system install web`, the Claude Agent SDK with
  `claude`), not in the base package. Released as 0.2.0.

> I mean we should have some default systems that are lightweight and I created

- **Decided (replaces "no systems"):** `fnloom start` runs a default set of the lightweight premade systems (small
  dependencies; one list in the code says which), live automatically. The heavy ones (web with puppeteer, claude with
  the Claude Agent SDK, and any with large drivers) stay out of the base package and pull their dependencies when
  installed.

> Widgets only make sense on top of database

- **Decided:** widgets is never a default on its own; it comes with database (both defaults if database is light,
  else installing database brings widgets).

## Status (2026-11-27, 0.2.0): released

- `fnloom@0.2.0` from the registry, clean prefix: 267 MB (0.1.0 was ~745 MB), no puppeteer or Claude Agent SDK.
  `fnloom start` runs fs, input, code, schedule, api (all live); `fnloom system install database --config …` brought
  widgets along, both live. The default set is `PREMADE` in `packages/cli/src/premade.ts`; database, web and claude
  ship as zips and fetch their own dependencies on install.
- Node 22.21+ now required: installed systems reach the network through the hub's proxy (`NODE_USE_ENV_PROXY`).
- Open: database/google-calendar/embedder/ollama declare no network grant, so an installed Postgres/SQL Server database
  would be refused by the proxy (SQLite is fine); claude installed from its zip is untested; installed systems don't
  see the hub's environment (web needs its Tavily key in its config).
