## Phil's words (verbatim)

> something that really sells this as a next Gen harness. I want you to do a feature matrix of the major players and

## Approach

1. **Research, in parallel:**
   - `docs/site/research/competitors.md`: OpenCode, Claude, herdr and the most popular agent harnesses, each claim
     with a source and the date it was checked.
   - `docs/site/research/harness-features.md`: every harness feature that exists and works, with a 1-5 word label,
     a one-line explanation and its evidence, grouped into categories.
2. **The matrix:** categories (8-12) as sections, each with its 4-8 headline features as rows, so no table is
   100 rows tall. Every label is 1-5 plain words. Cells are yes / partial / no, with sources for the competitors.
   The harness's rows come only from what is built and tested.
3. **The site (gh-pages):**
   - a page that sells the harness as a next-gen harness: a hero, what makes it different, the categorized
     matrix, and how it works, with screenshots of the real web app;
   - built as a static page and published on the repo's GitHub Pages.
4. **Review:** the matrix and a page draft go to Phil in hitl before anything is published.

### What this asks for

1. **The name stays a variable.** One config value; the build writes it everywhere (title, meta, copy, matrix,
   marketplace). No name is hard-coded in the source pages.
2. **No test numbers on the site.** The "Tested like a family uses it" section loses its pass/weak/fail figures (the
   simulated-family testing can still be described without numbers, or the section goes).
3. **Categories ordered by what's unique or strongest**, first to last, with the weakest (where you use it: no desktop
   app) last.
4. **pi (pi.dev, "pi.dec" in Phil's note) joins the comparison** as a column, researched like the others.
5. **Animated and dynamic, like Oryoli's home page** (`oryoli/packages/app/src/landing/`: drawn step-through demos
   that play while on screen, a phone that leans toward the pointer, floating notes, a marquee, a carousel, reveal on
   scroll, still under reduced motion). It has to be obvious how useful and better it is.
6. **A system marketplace** (queued; plan in `marketplace-2026-11-26.md`): a service Phil runs and owns that lists
   systems people publish in public repos (under known directories). For now a mock marketplace with a real, polished
   front page in the site; later its own service.
7. **Hosting: Phil's own domain on DigitalOcean** (not GitHub Pages). The site builds to a static folder.
8. **Same experience on every device:** emphasized.
9. **Out-of-the-box systems:** databases, Claude Code, APIs, MCP, the context layer, the research layer, and the rest.
10. **Study the competitors' own sites and out-do them.**
