## The work

1. **Search decisions and suggestions.** `hubOptions.fnsSearchDecision` and `hubOptions.contextSearchDecision`, chosen
   by an admin like "Who picks" (`suggestDecision`): none, a decision model, or an LLM. When one is set, the hits of
   `hub/fns_search` (fns, and context for the context one) go through it and only the ones it keeps are returned.
   `suggestDecision: none` suggests the top K by similarity over the threshold. Search ranking stops putting
   developer, authoring and admin material ahead of what an ordinary request needs (diagnosis fixes 1 and 5).
2. **Citations.** The chat option "Use citations", as Phil describes above.
3. **The prompt rewrite**, per [prompt-rewrite-2026-11-21.md](prompt-rewrite-2026-11-21.md) and iteration 1's
   diagnosis: system prompt, systems list, every tool's description with at least one example in tools mode, fn and
   kind instructions, context items.
4. **Hub behaviour fixes from the diagnosis:**
   - the form result that says "Nobody is watching this run… Don't wait for them: go on";
   - attachments reaching the model as resources it can read;
   - short validation errors that name the path and the expected shape;
   - an output-token cap on authoring steps (GPT-6 Luna looped whitespace for 65k tokens);
   - the event-loop stall that made the hub shed load ("the hub is busy") in rep 3;
   - the fs git hook reporting a repository whose root is outside the fs root.
5. **Runner:**
   - household variants: decision models on (decide role, suggestions, fns and context search decisions all set to a
     decision model) and off;
   - retry a 503 ("the hub is busy") with backoff;
   - the fake home folder outside the repository;
   - a report that compares the two variants case by case.
